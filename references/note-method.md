# 方法与规则细节（note-method）

## 为什么是"两阶段"

笔记的"结构"可确定性判定（章节是否存在、锚点是否有效、引文是否在原文中出现），
而"内容"需要语义理解。因此拆成：

- 阶段 1（脚本）：解析 + 骨架 + 段落到章节归属，产出可复核的锚点体系。
- 阶段 2（Agent + 脚本）：Agent 填语义字段，脚本确定性核验并给出待人工确认清单。

两阶段之间用内容哈希指纹复用：`--notes` 合并运行不重解析 PDF，保证确定性。

## 骨架与归属（对得上）

- 章节 `S1…SN` 取自 `parse_pdf.py` 识别出的标题层级，按页码+bbox 排序（阅读顺序）。
- 正文段 `T0001…` 复用 `segment.py` 的阅读顺序恢复；每个段归属到"最近出现的标题"
  章节（标题自身成为该章节的起点）。
- 无任何标题时，全篇归入隐式 `S0`，不伪造章节边界。

## 核验阈值与规则（找得回/留得住）

| 检查 | 规则 |
|-|-|
| 章节合法性 | `chapter_notes[].section_id` 必须 ∈ 骨架 `sections`；重复章节判错 |
| 章节顺序 | 笔记顺序与论文章节顺序一致，否则记 `warning`（人工复核） |
| 卡片完整性 | `research_question/data/method/conclusion/limitations` 五项非空 + `main_findings` ≥ 1 |
| 章节覆盖 | 每个骨架章节至少一条 `chapter_notes`，漏章节判错 |
| 锚点有效性 | `page ∈ [1,pages]`；`section_id` 有效；`segment_id` 有效 |
| 引文核验 | `quote` 去除空白并小写后，须为锚点处（段/章/页）原文的子串；找不到判"锚点失配" |
| 数字一致性（软） | 笔记 `text` 中长度 ≥2 的数字须在原文中出现过，否则记 `warning` 人工复核 |
| 可复用性 | 知识点 `id` 全篇唯一 |

`issues`（硬核验失败）→ `status=partial`；`warnings` → 只进 `uncertainties`，不阻断。

## 为什么引文（quote）是核心核验机制

摘要式笔记最易"看似通顺、实则失真"。要求每条关键笔记携带**原文逐字摘录**并回到
锚点处查找，把"能否复核"变成机器可判的字符串包含判定；无法摘录（如跨段概括）处
需在 `note` 说明，由人复核。数值/单位另做软一致性检查，抓"结论写对但数字写错"。
